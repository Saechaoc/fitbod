## What the authored journey proves

`MilestoneOneJourneyUITests.testAuthorRoutineLogRelaunchFinishAndHistory`:

1. Combine Chest + Barbell filters with search; exercise no-match and clear
   paths. Validate an empty custom exercise, create a long-named custom exercise
   and open its detail.
2. Create `M1 Upper Body` and `M1 Push A`; add the custom exercise and Incline
   Dumbbell Press. Assert the unsaved session name survives the nested picker.
3. Move exercises in both directions and assert their order. Save, reopen
   editing, change target sets/reps and start a workout.
4. Append and swipe-delete a set; enter **80 lb × 8**, complete it and adjust rest
   both directions.
5. Terminate and relaunch **without reset**. Resume; assert reps **8** survived
   and the rest dock restored its absolute deadline.
6. Finish, view the summary, navigate to history and reopen the completed
   workout. Assert its name and **640 lb** working volume.
7. Start another workout and observe **Previous: 80 × 8**; discard this unlogged
   workout with confirmation.

The authored journey starts with a fresh dedicated test store, not a demo
workout. Reset occurs only on initial launch, never on relaunch.

The layout case uses a demo fixture to isolate layout, numeric/action targets
of at least 44pt, screen bounds, keyboard Done, rest ±15/Skip, expanded timer
controls and Finish. The gallery case verifies real Signal/Compact action
feedback and captures inputs. The test scroll helper requires full viewport
visibility: XCUITest can report covered or barely-visible cells as “hittable.”

## Focused persistence, snapshots and recovery

- `MilestoneOnePersistenceTests.persistedWorkoutJourney` releases disk-backed
  containers and reopens SQLite. It reads completed **80 × 8** and an unfinished
  added **82.5 × 6** set, then reopens completed history after upstream name,
  sets, rep-range and rest changes. Workout names and **3 × 5–8 / 180s**
  prescriptions stay frozen.
- `bodyweightCompletionAndPreviousPerformance` accepts zero added load for
  bodyweight/weighted-bodyweight and preserves prior reps. Empty loaded,
  negative/non-finite weights and zero-rep entries cannot complete.
- `SessionSnapshotFidelityTests`, `SessionBlockSnapshotTests`,
  `RestTimerEngineTests`, `RestTimerPersistenceTests` and store-recovery suites
  are included in the full unit run. Timer checks cover absolute deadlines,
  adjustment, restoration and session isolation.

## Reproduce

Use a dedicated simulator: milestone UI tests reset its initial test store.
Choose an available UUID with `xcrun simctl list devices available`.

```sh
xcodebuild -project fitbod.xcodeproj -scheme fitbod \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath /private/tmp/fitbod-m1-build \
  build CODE_SIGNING_ALLOWED=NO

xcodebuild -project fitbod.xcodeproj -scheme fitbod \
  -destination 'platform=iOS Simulator,id=SIMULATOR_ID' \
  -derivedDataPath /private/tmp/fitbod-m1-tests \
  -parallel-testing-enabled NO \
  -only-testing:fitbodTests \
  -only-testing:fitbodUITests/MilestoneOneJourneyUITests \
  -resultBundlePath /private/tmp/fitbod-m1-results.xcresult \
  test CODE_SIGNING_ALLOWED=NO

xcrun simctl ui SIMULATOR_ID content_size accessibility-extra-large
xcrun simctl ui SIMULATOR_ID appearance dark
# Rerun testWorkoutLayoutAndTouchTargets and testComponentGalleryInteractions.
# Restore defaults after review:
xcrun simctl ui SIMULATOR_ID content_size large
xcrun simctl ui SIMULATOR_ID appearance light

python3 docs/design-system/tokens_check.py
git diff --check
```

Tested larger text is `accessibility-extra-large` / SwiftUI `.accessibility3`,
with no fixed in-app size override. Default-size authoring and accessibility
logger/gallery checks are separate cases, not a claim that every block or
analytics screen has received the same runtime coverage.

## Explicit limits

Physical VoiceOver navigation, haptics, notification authorization, Live
Activity/Dynamic Island behavior and populated backup/sync round-trips were not
demonstrated. They remain release checks in [ROADMAP.md](../ROADMAP.md).

The local store/catalog needs no backend. These runs did not separately disable
the host network or test optional remote imagery. The color checker proves
approved token combinations, not every pixel of every existing screen.

The existing `Text` concatenation deprecation in `BlockBuilderView` and the
simulator LLDB version-store diagnostic are non-fatal warnings. Codex made no
commits, pushes, branch changes, blanket staging or destructive cleanup.
