# Open decisions

Product calls the proposal does not make for the user.
Each names the default the layouts assume, so the build can start without the answer and change later.
Defaults marked "round 1" were set or changed by the adversarial review; [review-log.md](review-log.md) has the reasons.

| # | Question | Default in the layouts | The other way |
| --- | --- | --- | --- |
| O-1 | Drop the day streak? | Dropped. Nothing on Today or Progress shows it. | Keep a streak on Progress, counted by training weeks rather than days, which is a new feature. |
| O-2 | Should a workout started from the session sheet move a rotation block forward? | Yes (round 1; the rule fixed in round 2). A sheet row of the active block's routine passes the resolver's next slot when it holds that session, else the first slot after it that holds the session, wrapping, so a session slotted twice never moves the rotation backwards. With no block the row passes its routine slot under the same rule, anchored at the T-PICK suggestion. A session outside the routine starts unslotted and moves nothing. In a rotation block a row that is not NEXT says what it skips ("skips Pull A, Legs A"), because the anchor moves past those slots for this cycle. | No: every sheet start unslotted, so a double or a swapped session never moves the rotation and the skipped session is offered again (D-19). |
| O-3 | What counts as done for today? | Any workout with logged sets that started today and has finished, slotted or not, with or without a block (round 1). The slab's "Next" line names the resolver's next slot, or nothing. | Only a workout logged for today's slot. An unslotted workout leaves the planned session up. |
| O-4 | Keep the automatic weekly recap sheet? | Kept: once per week on Today's first appear when due, with "Recaps ›" on Progress per the approved all-recaps mock-up. It no longer waits for a block review (round 1). | Replace the sheet with a notice row, "Week 2 recap ready ›", so nothing opens by itself. |
| O-5 | Surface a finished block's review while a newer block is active? | No (round 1). `pendingReviewBlocks` returns nothing while a block is active, and its tests pin that, so Today shows no notice; the review opens from Program › Past blocks. This also means the notice above T-READY's START BLOCK ▸ goes when the lifter taps that button; the notice sits first, so it is seen before the start (round 2). | A notice row in that case too, kept until the review is opened or dismissed, which needs a new query over the pinned contract, a dismissal, and a second notice on T-TODAY beside the deload advisory. |
| O-6 | Which ready block takes START BLOCK ▸ when there are several? | The oldest saved (`startDate`, which the builder stamps at save and `start` overwrites), then by name (round 1; reworded in round 2 because no screen plans a start). Program's Planned cards show "Saved Oct 3", so same-name blocks saved on different days read apart. | None until the lifter picks on Program, or a real planned start (O-14). |
| O-7 | Do the routine folders ship? | No. RoutinesListView stays unwired and out of the product; the RoutineFolder model stays in the schema. Deleting the view is a Phase 3 cleanup. | Wire folders into Program's routines section as collapsible groups. |
| O-8 | Where do block presets live? | Only inside + New block › Use preset. | Also as a section on the empty Program screen, as now. |
| O-9 | Should Program's "This week" rows act? | Logged rows open the workout; the TODAY ▸ row starts the scheduled session with its slot; the rest are read-only. | All rows read-only. |
| O-10 | Plan complete: a line into Block overview, or an automatic end? | The plan line's second line reads "Plan complete" and opens Block overview, where End block stays with the consequence in its dialog (round 1). Today itself has no End block. | Automatic end on the first appear after the plan's last day, with the review as the next thing shown. |
| O-11 | Should the exercise rows on Today open anything? | No, as now. The section head's "View ›" opens the session detail. | Rows open the exercise's progress screen. |
| O-12 | Can a block be planned from Today? | No (round 1). Program › + New is the one entry; Today starts a ready block and nothing else. The one exception is the review sheet's own "Start next ▸", which opens the builder from BlockReviewView, not from Today (round 2). | A "Plan a block ›" ghost on T-PICK opening Program's start-choice sheet, which means sharing the sheet and its staging state between the tabs. |
| O-13 | Week cells on Program's Now slab? | No (round 1). The slab shows the name, "Week 2 of 6 · Accumulation" and the routine; the cells stay on Block overview. | The mock-up's phase-labelled cells in place of the caption. |
| O-14 | Should a block carry a planned start date? | No (round 2). `Block.startDate` is the save date until `start` stamps the real start; Program shows "Saved Oct 3", and Today treats every ready block as the next action from the day it is saved. | A planned start set in the builder, which is a Schema V8 attribute; Today would then lead with the ready block only from that date, and same-name blocks would read apart by plan rather than by save day. |
