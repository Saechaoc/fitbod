# Risks

What could go wrong in the build, and how each is contained.
Design decisions and their alternatives live in [tradeoffs.md](tradeoffs.md).
Rows marked "round 1" were added or corrected after the adversarial review.

| # | Risk | Mitigation |
| --- | --- | --- |
| R-1 | Tests pinned to removed copy, identifiers or files fail: the strip, the band, StartBlockCTA, DeloadWeekBanner, "NO PROGRAM", "DEFINE BLOCK", "SESSIONS DONE", the band's uppercased block name ("LIVE BLOCK" is the `-fitbod-seed-active-block` block's name, which two UI suites match as a whole label with `label ==[c]`), `today.sessions`, and suites that read source files by path. | Every step in [plan.md](plan.md) names its suites, from an `rg` over `fitbodTests` and `fitbodUITests` for each removed string and type (round 1). "CREATE BLOCK" and the new-block sheets stay in ProgramView.swift, so the three New Block guardrail suites stay green; they run on every ProgramView edit anyway. |
| R-2 | Removing the stat strip removes Today's only entry to history and the `today.sessions` identifier that seven UI suites use, two of them as the "Today has loaded" signal (round 1). | History stays on Progress and the T-DONE slab opens the finished workout. A `today.root` identifier on the header bar, present in every state, replaces the loaded signal; the suites move their history entry to Progress › History. |
| R-3 | A wrong hero after a block ends (round 1): the draft put a review hero above the ready block, and the review is acknowledged only by "Start next ▸", so it could never clear. | The review is a notice row, closing it by any route acknowledges, and T-READY leads. `TodayState` is a pure function with a unit test per row of the state table, including "review closed with Plan custom → T-READY" and "block active → no notice". |
| R-4 | Done-for-today misfires across midnight, time zones, or an app left open overnight (round 1). | `TodayState` reads the calendar from the environment, attributes a workout to the day of its `startedAt`, and TodayView re-evaluates when the scene becomes active and on the significant-time-change notification. The ghost "Start another workout" always exists, so a wrong DONE costs one tap. |
| R-5 | Rotation anchor: a workout from the session sheet must move a rotation block only when it belongs to the active routine, and a session slotted twice (the slot picker allows it) must not move the anchor backwards (round 1, round 2). | Sheet rows pass the slot only for sessions in the active block's routine: the resolver's next slot, or the first after it that holds the session, wrapping. `TodayResolver`'s anchor rule is unchanged. Unit tests start the active routine's next session from the sheet and check the following resolution, and cover a session in two slots. A no-block start passes its routine slot, which the resolver ignores for any later block because it filters by block. |
| R-6 | Two week-and-phase readouts (Today's plan line, Program's Now slab, Block overview's strip header) drift apart. | One formatter, `BlockPosition.label(block, on:)`, used by all three, with one unit test including the plan-complete case. |
| R-7 | The this-week row keeps the volume model's cost on every Today render, counts an open workout's sets, or shows last week's numbers on Monday (round 1, round 2). | The row counts working sets with `FatigueModel.completedWorkingSets`, not `weeklyVolumes`, filtered to `countedWorkouts`, inside a `.task(id:)` keyed on the finished workout IDs and the week start from `mondayAtMidnightForToday`, never in `body`. Progress › Volume is pushed, so the full model runs only when opened. |
| R-8 | The plan line overflows at 390pt with a long block name (round 1): one line holds about 44 characters of `labelSmall`, and "SPRING BLOCK · WEEK 6 OF 6 · INTENSIFICATION" is already 44. | Two Texts in a VStack: the name tail-truncates with `lineLimit(1)`; the position line never truncates. At accessibility sizes the name wraps to two lines. A long-name seed and the `today--long-name` capture are acceptance for step 1.1. |
| R-9 | Program's "+ New" via `HeaderSlot.action` renders orange and with a smaller target than the old chrome's 44pt (round 1). | Use the `HeaderAction` form, which is ink by default, keep the `onGeometryChange` height measurement the popover depends on, and check the target on the 17e capture. UI suites match "+ NEW" without case, so the label change alone breaks none. |
| R-10 | Starting a ready block from Today or Program's slab can throw, because `derivedStatus` is live and the overview swallows the error with `try?` (round 1). | Both buttons catch the error and show "Couldn't start block" with "Try again" and "Open block". T-READY and the P-PLANNED slab show only when no block is active, so `start` never takes its swap path from them. |
| R-11 | The Program Now slab repeats what Block overview shows, so the page gains elements (round 1: the draft had eleven above the fold). | The slab is four lines with no cells, days left or training days; P-ACTIVE counts eight in `screen_budget.py`. P-RESUME is ten and accepted as transient. |
| R-12 | The session sheet starts a workout on a row tap, so a mis-tap opens the logger (round 1: the draft understated the cost). | The logger's ‹ leaves the empty workout open, Today shows RESUME, and its DISCARD asks nothing when no sets are logged, so the cost is two taps and no logger change. |
| R-13 | decisions.md stages D-159 as "when stable" and D-341 as "polish later", but this plan closes them in Phase 1 because their elements are replaced. | The bundle's landing adds a note under decisions.md's stage lists naming the two rows (D-159, D-341) whose stage this plan would change; the lists themselves move only when the user confirms, because decisions.md records the user's review. |
| R-14 | The prototype stage guide defers polish until a workflow is stable; a redesign this wide could be read as polish. | The brief asks for an information-architecture change, which the guide calls the time to rebuild a screen ("With the redesign" in decisions.md). Phase 1 is restructuring, not finish; VoiceOver and AX3 passes stay deferred to Phase 3 as the guide says. |
| R-15 | Dark mode and AX3 regressions in new slabs. | Phase 1 acceptance runs the 17e light and dark captures; AX3 waits for Phase 3 per the development guide. |
| R-16 | GitNexus marks `TodayView.body` and `ProgramView.body` as high-impact symbols. | Each step runs `gitnexus_impact` before editing and reports the blast radius, as the project rules require. |
| R-17 | Deload counts (round 1): the hero and sublines read raw `targetSets`, while `SessionFactory` cuts working sets to `max(1, floor(targetSets × volumeMultiplier))` in a deload phase and `WarmupRamp` skips warm-ups; the two could keep disagreeing, or the factory's rule could change without Today following. | `workingSetCount(targetSets:phase:)` holds the rule and the factory, the hero and the sublines all call it, with a unit test per branch. Warm-ups stay the factory's: the sublines drop the fixed "2 warm-up", which the factory never read, rather than guess a ramp Today cannot compute (round 2). |
| R-18 | Acknowledging the review on close changes BlockReviewView's behaviour and the pinned sheet wiring in `BlockReviewTriggerTests` (round 1). | Step 2.1 rewrites the wiring assertion and keeps the `pendingReviewBlocks` contract tests untouched; `BlockReviewAfterEndUITests` taps the notice instead of waiting for the sheet. |
| R-19 | The acceptance captures need states no DEBUG seed produces: a ready block with none active, a session with no exercises, a workout finished today under a block (round 1; cut from five to three in round 2, because `-fitbod-seed-powerbuilding` has the long name, `-fitbod-seed-empty-workout` a workout finished today with no block, and `-fitbod-seed-ended-block-recap` routines with no live block). | Step 1.3 adds the three seeds and their launch arguments; step 1.1 captures the long name from the powerbuilding seed; each later step names the seed its captures use. |
| R-20 | The weekly recap waited for the review sheet's `onDismiss`; without the automatic sheet it needs a new trigger (round 1). | The recap shows on first appear when due and waits for nothing; `WeeklyRecapUITests` moves to `today.root`. |
| R-21 | Moving FatigueSurfaceView to Progress loses the advisory ring, because `isAdvisoryActive` came from Today (round 1). | `VolumeScreen` evaluates `DeloadAdvisor` on appear and passes the result in, on both tabs. |
| R-22 | Program's This week rows disagree with Today's hero after an off-plan or swapped workout (round 1). | Rows list logged workouts on the day they happened and planned sessions only for days without one; the row model has a unit test for an off-plan day, a swapped day and a done day, and acceptance compares the rows with Today's hero. |
| R-23 | `Block.startDate` reads as a planned start when it is only the save date: the builder stamps `.now` and `start` overwrites it (round 2). | No copy says "starts" or "planned"; Planned cards say "Saved Oct 3"; O-6 orders ready blocks by oldest saved; a real planned start is O-14 and a schema change. |
