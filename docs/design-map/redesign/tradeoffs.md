# Tradeoffs

Each design decision, the alternatives rejected, and why.
Failure modes live in [risks.md](risks.md); product calls the user still owns live in [open-decisions.md](open-decisions.md).
Decisions marked "round 1" replaced a draft choice after the adversarial review; [review-log.md](review-log.md) has the findings.

## Today

| Decision | Alternatives rejected | Why |
| --- | --- | --- |
| Move the volume list and heatmap to Progress › Volume; keep one volume row on Today. | (a) Collapse the surface under a disclosure on Today. (b) Give volume its own tab. | (a) keeps four screens of content on the page and a disclosure the lifter opens once and leaves open. (b) adds a fifth tab for one screen. Progress is the tab for analysis and lacks the entry (D-131). |
| The volume row shows two raw counts, "2 workouts · 20 sets", and no muscle cue (round 1); its label is "VOLUME THIS WEEK" (round 3). | (a) The weighted total with a delta, as the volume slab shows it. (b) "3 muscles under MEV ›" in the row. (c) The label "THIS WEEK". | (a) counts one bench set three times, so the row and the hero's "15 SETS" would use one word for two numbers. (b) is true on most days early in the week, so it reads as a standing warning, which is the noise A-11 removes. The muscle cue is one tap away on Volume. (c) does not say where the row goes, and the five-second test wants the destination named. |
| The block repair slabs (empty routine, empty session, no routine) keep a "Choose another session ›" ghost when a session with exercises exists anywhere (round 3). | (a) The repair action alone, as draft v3 had for the empty-routine and no-routine slabs. (b) The inline picker under the slab, as main shows it. | (a) loses the alternate start main's picker offers in exactly these states (D-163), so a lifter whose block broke could not train from Today. (b) puts a list of signal buttons under a repair message. The ghost costs one row and leads to the same sheet as every other state. |
| The deload advisory shows with or without an active block and yields to a pending review notice (round 3). | (a) Gate the advisory on an active block, as drafts v2 and v3 did to keep one notice per state. | (a) removed an advisory main already shows without a block (`refreshAdvisory` checks only the setting) with no decision recorded. Precedence keeps one notice per state at no cost: the review clears on its first close, and the advisory returns right after. |
| Replace the stat strip, block band and week cells with one plan line, drawn as two lines (round 1). | (a) Keep the band and drop the strip. (b) Keep the strip and make the band a button. (c) One line with a truncated name. | (a) and (b) keep two block readouts above the action (A-02). One row answers "where am I in the block" and is the one route to the block's actions. (c) hides the name or the week on long names at 390pt. The week cells stay on Block overview, one tap away. |
| Drop the day streak. | (a) Keep it in the plan line. (b) Move it to Progress. | The streak counts consecutive days with a workout ending today or yesterday, so a rest day between workouts breaks it and it reads 1 or 2 for a lifter on a three to five day split (A-03, corrected in round 3). A workout streak by week would be a new feature. Listed in open-decisions.md. |
| Label the hero "TODAY" (weekday) or "NEXT UP · 2 OF 3" (rotation) and drop "DAY 04 / 28" (round 1). | (a) Keep "NEXT". (b) Keep the day counter. (c) "TODAY · THURSDAY". | "NEXT" reads as a queue. The day counter is a number nobody trains by. The header already shows the weekday. A rotation lifter still needs to know where the cycle is, so the rotation label carries "2 of 3". |
| Put the session picker in a sheet behind one ghost row. | (a) Keep rows inline under the hero. (b) Keep the picker hidden while a session is scheduled. | Inline rows put several start affordances under the one that matters. Hidden is the D-163 dead end. One ghost row costs one tap and reads as secondary. |
| Routine rows in the session sheet start the workout on tap; "Other sessions" rows open the session's detail (round 3). | (a) Row opens the session detail and a button starts it, as the picker does now. (b) "Other sessions" rows start on tap too. | Two actions per row doubled the targets and made four orange buttons (A-17). Starting is cheap: the logger shows the exercises, and a mis-tap costs two taps (the logger's back, then DISCARD on the resume slab, which asks nothing when no sets are logged). A routine session's detail stays one tap away from the exercise head on Today and three taps away through Program; accepted, because previewing a session that is not today's is not an everyday job. (b) leaves a session in no routine with no preview or repair route at all, since no routine screen lists it. |
| A sheet row passes its slot when the session belongs to the active block's routine: NEXT, or the first slot after NEXT that holds the session (round 1; the rule fixed in round 2; NEXT defined per scheduling mode in round 3). | (a) Every sheet start unslotted. (b) One row per slot, so a session slotted twice lists twice. (c) One NEXT rule for both modes: the resolver's result for today. | Unslotted doubles and swaps never move a rotation block, so the skipped session is offered again the next day (D-19, staged "with the redesign"). (b) doubles the rows of a PPL ×2 routine for the same choice. (c) is undefined on a fixed-weekly rest day (`resolveFixedWeekly` returns `.restDay`) and names today's finished slot again after a workout, while T-DONE names the next training day; so NEXT in weekday mode is today's slot until a counted workout starts, then the next training day's. TodayResolver's anchor rule does not change; one helper, `StartSlot`, supplies the slot to every start route, and the "skips …" subline says what a swap leaves out. |
| Preview-and-start from the session detail carries the slot: the detail takes a `routine: Split?` and computes the slot with `StartSlot` when Start is tapped (round 3). | (a) Leave the detail's Start unslotted, as now (`SessionTemplateDetailView.swift:210-211`). (b) Pass the slot into the detail when it opens. | (a) reopens D-19 through Today's "View ›", ADD EXERCISES ▸ and Program › routine › session: a workout started after a preview never moves the rotation. (b) can pass a slot the lifter deletes while editing the routine from that same screen; computing at tap time cannot. |
| Start a ready block from Today. | (a) Only from Block overview. | After a block ends, Today's "START A BLOCK" creates a blank block even when a ready one waits (D-25). The ready block is the planned next action and belongs on the screen that answers "what now". |
| A pending review is a notice row, not a hero and not an automatic sheet (round 1). | (a) Keep the sheet on first appear. (b) A hero with REVIEW BLOCK ▸ that outranks the ready block. | The sheet shows once and then the review is unreachable (D-27, D-40). The hero could never clear, because only "Start next ▸" marks a review seen, and it hid START BLOCK ▸ for good. A notice row leaves the hero to the next action and clears itself. |
| Closing the review by any route marks it reviewed (round 1). | (a) Only "Start next ▸" marks it, as now. | A review the lifter opened and read is reviewed; the current rule is the known bug D-06. The review stays reachable from Past blocks, so nothing is lost by clearing the notice. |
| Plan complete is the plan line's second line, opening Block overview (round 1). | (a) End the block automatically when the plan is over. (b) A notice row on Today with END BLOCK ▸. (c) Keep a status chip only. | Ending writes the archive (freeze #2) and the lifter may be finishing a week late. A Today row could end the block in the middle of its last workout, and needs the overview's dialog moved into a shared modifier. (c) gives no action (D-166). The line costs one tap more than (b) and keeps one End block. |
| Deload week is a word in the plan line, a caption in the hero, and working-set counts after the phase's volume multiplier; the sublines show no warm-up count (round 1; working sets only in round 2). | (a) Keep the banner. (b) Keep the chip. (c) Drop the banner and keep raw template counts. (d) Keep a warm-up count in the sublines. | Three deload alarms for a planned week (A-20). (c) would show full volume beside "lighter sets"; the counts carry the cut once the multiplier applies, which is code work in step 1.2. (d) is a guess: the factory ramps only the first compound from the top weight and the bar, and never read the row's flag, so the fixed "2 warm-up" was wrong on most rows. |
| Done-for-today is a paper slab with no signal, for any finished workout started today, with or without a block (round 1); with several, one name row per workout, newest first (round 3). | (a) Show the next session at once (current rotation behaviour). (b) Hide the hero. (c) Count only slotted workouts. (d) Show only the latest workout when there are two. | The lifter needs to see the day is done and what comes next, and not be offered a second workout as the primary action (D-164). (c) leaves A-09 open for every sheet start and for lifters with no block. (d) hides a logged workout behind a slab that looks complete; a second row costs one line. "Start another workout" stays as a ghost. |
| T-DONE outranks T-READY; T-READY outranks T-PICK (round 2). | (a) T-READY first always. (b) A "Start Summer Block ›" ghost on T-DONE. (c) T-PICK first while a ready block waits. | (a) hides "done for today" every training day a ready block waits and offers a block start right after a workout. (b) is a ghost row that starts a block, a weight the ghost style does not carry; Program's slab keeps the one-tap start and Today offers the block again the next day. (c) buries the planned next action; a block is built to be started, and "Start a workout instead ›" costs one tap. A real planned start date would settle it (O-14). |
| At most one notice row per state (round 1). | (a) Stack up to three (deload, review, plan complete). | Three rows push the action to the fifth element and break the two-before-the-action budget. Plan complete lives in the plan line, and the review notice shows only without a block, so the two never coincide. |
| The review notice goes when the ready block under it starts (round 2, accepted). | (a) Keep the notice while the next block is active until it is opened or dismissed. | (a) needs a new query over the pinned `pendingReviewBlocks` contract, a dismissal, and a second notice on T-TODAY beside the advisory. The notice sits directly above START BLOCK ▸, so the lifter sees it before starting, and the review waits in Past blocks (O-5). |
| T-FIRST is only the fresh store: no block, no live routine, no session with exercises. A session with exercises in no routine makes Today T-PICK with that session as the hero; a live routine with no usable session makes Today T-FIX (round 3, replacing round 2's ghost). | (a) T-FIRST shows nothing else and such a session is unreachable. (b) Round 2's "Start a workout ›" ghost on T-FIRST. (c) T-FIRST for a routine with no exercises. | (a) left D-24 half open. (b) put "Build your first routine" over a lifter who has a session to train from, and a ghost over the only way to start. (c) tells a lifter who built a routine to build one; the T-FIX slab names the routine and leads to it. A fresh store still shows one button. |
| Fresh store shows only "Build your first routine", and Today never creates a block (round 1). | (a) Keep the block offer too. (b) A "Plan a block ›" ghost on T-PICK. (c) Show a sample routine. | Two orange calls and a block flow that opens a blank picker (D-24, D-162). (b) needs Program's start-choice sheet and its staging state shared between tabs, and two guardrail suites pin them in ProgramView.swift. (c) is a product feature, not a layout fix. |
| Keep "A routine is your split, like Push / Pull / Legs." (round 1, accepted) | (a) "A routine bundles your sessions." | "Split" is the gym word for a training split and the sentence defines the app's word with it. The glossary bans the code name `Split` from copy, not the English word. |
| Keep "Fitbod / Today" in the header. | (a) "Today" only. | The brand line is the same on four tabs and a test pins it; changing it gains nothing. |

## Program

| Decision | Alternatives rejected | Why |
| --- | --- | --- |
| An ink Now slab for the active block, first on the page. | (a) Keep the card list ordered active → ready → draft → done. (b) Move the active block's detail to Today. | The list answers "what exists" (A-23). The user's own mock-up (`phase-2--program.png`) puts the active block as a hero with its routine, and it was never built. Today already carries the block's position in the plan line; Program is where its structure belongs. |
| The Now slab has four lines and no week cells, days left or training days (round 1). | (a) The mock-up's phase-labelled cells. (b) "12 days left". (c) "Push Pull Legs · Mon Wed Fri". | The draft slab told the week three times and put eleven elements above the fold. The cells are on Block overview one tap away. An active block stores no end date, and days left says what "Week 2 of 6" says. The training days are the rows directly under the slab. |
| This week rows on Program, not Today; logged workouts list on the day they happened; "TODAY ▸" is the page's one forward action (round 1). Days are groups with one row per counted workout, the open workout on its day, and "TODAY ▸" shows exactly while Today's state is T-TODAY (round 3). | (a) Put the week's days on Today. (b) Rows from the plan only. (c) Read-only rows. (d) One row per day, showing the latest workout. (e) Program's own rule for when "TODAY ▸" shows. | Today is about now; the week's shape is planning. (b) shows "TUE Rest" over a Tuesday workout and the planned session over a swap. (c) drops the mock-up's one action and leaves P-ACTIVE without a next step. (d) hides the second workout of a day and has no rule for which one the row opens. (e) was missing the open-workout, empty-session and done-today guards Today has; one `TodayState` from one set of inputs cannot disagree with itself (R-24). |
| Past blocks are a pushed list behind one row. | (a) Keep DONE cards inline with ALL HISTORY after three. | Finished blocks shared the list with current work (A-24). One row with a count keeps them one tap away and the list can carry dates (D-127). |
| READY and DRAFT chips are outlined ink; Program draws no filled chip (round 2 wording). | (a) Keep READY in outlined signal. (b) An ACTIVE chip on the Now slab. | Two accent chips compete (A-24, P-7). READY earns a signal button only when nothing is active, and then the button, not the chip, carries it. (b) repeats the slab's own "● Active block" label row. |
| Planned cards and both ready slabs show "Created Oct 3", not a planned start and not "Saved" (round 2; the word and the slab caption in round 3). | (a) "Starts Jun 30" from `startDate`. (b) No date. (c) "Saved Oct 3". | `startDate` is stamped when the draft is created, kept on edit and overwritten at start, and no screen plans a start, so (a) showed a past date as a plan. (b) leaves same-name blocks alike and hides why one ready block leads. (c) is wrong after an edit: the date does not move when the block is saved again. A real planned start is O-14. |
| With drafts only, the newest draft leads Program as a paper slab with CONTINUE BLOCK ▸ in ink (round 3). | (a) Cards only, as for ready blocks. (b) The oldest draft leads, like the ready rule. | (a) leaves P-PLANNED without a primary task when nothing can be started. (b) orders by the wrong thing: the draft the lifter touched last is the one they are building, and drafts have no "next to start" order. No signal, because a draft cannot be started. |
| Past blocks show the year when a block ended in an earlier year than today (round 3). | (a) Never. (b) Always. | (a) leaves "Nov 4 - Dec 1" ambiguous once a year has passed, the case D-127 is about. (b) spends width on every row for the common case. |
| Routine rows get a muted "used by" subline instead of chips. | (a) Keep the chip flow. | Chips read as controls (P-11) and stack when two blocks share a routine. A subline says the same in words. |
| Empty Program is routine-first and keeps the archived routines entry (round 1). | (a) Keep NO PROGRAM and + DEFINE BLOCK. (b) Keep the template section. (c) Hide the archived entry on the empty screen. | A block needs a routine; the first action must be the routine (D-162). Templates live in Use preset, one tap into + New block. (c) strands a lifter who archived everything. |
| The header's + New popover is the one creation entry in non-empty states, drawn with `HeaderAction` in ink (round 1). | (a) Keep + DEFINE BLOCK rows. (b) `HeaderSlot.action`. | Creation moved after the first block (D-125). (b) renders in the signal colour and shrinks the target; the `HeaderAction` form is ink by default. Empty sections keep a signal text link so an empty section still names its action (P-12). |
| BRUHeaderBar on Program. | (a) Keep ProgramChromeHeader. | Four tabs, one chrome (A-28). |
| The resume banner is a paper row holding the only signal; the Now slab stays ink; every other signal control draws in ink while it shows, on every underlying state (round 1; the ink rule for START BLOCK ▸, + NEW ROUTINE and + NEW BLOCK in round 3). | (a) Flip the Now slab to paper and recolour the chips while a workout is open. (b) Leave START BLOCK ▸ orange under the banner. | (a) restyled the whole page for an unrelated open workout. (b) puts two signals on P-PLANNED with a workout open, and the second one starts a block mid-workout. One element appears and the others keep their place in ink. |
| The resume banner's Discard is a visible ghost button that asks only when sets are logged, the rule Today's slab uses (round 3 made the rule shared). | (a) Keep the long-press menu. (b) Keep the banner's always-confirm alert. | Hidden gesture for a destructive action (D-56, D-57). (b) makes the same action ask on one tab and not on the other. An empty workout has nothing to lose, so the ask protects nothing; the exception is written into `docs/design-system/interaction.md` in step 1.6 so the confirmation rule stays honest. |
| "CREATE BLOCK" and the two new-block sheets stay in ProgramView.swift (round 1). | (a) Rename to NEW BLOCK and move the sheets to their own file. | Two guardrail suites pin the title and the full-screen cover in that file, and the sheets chain through Program's staging state. Today no longer needs them (O-12), so the move buys nothing. |
| The review opens from Block overview as a sheet with an origin parameter (round 1), and Block overview takes its own `origin` from the stack that pushed it (round 3). | (a) Push it. (b) Hard-code `.program` for reviews opened from Block overview. | BlockReviewView wraps its own NavigationStack, so a push nests two stacks. Its builder hard-codes Today as the origin, so the parameter fixes the back label. (b) is wrong when Block overview was pushed from Today's plan line or T-READY's Open ›, which both tabs do. |
