# Implementation plan

Three phases, ordered by how much clarity each step buys.
Phase 1 changes no data model and adds no state the app cannot already derive from stored fields.
Phase 2 changes behaviour: the review notice, the next-day lines, Program's week rows and the Block overview details.
Phase 3 holds the open decisions, cleanup and the accessibility pass the development guide defers.

Every step runs through a GSD command, runs `gitnexus_impact` on each symbol it edits before editing, and runs its suites serially on the dedicated simulators (`-parallel-testing-enabled NO`).
Three suites read `ProgramView.swift` by path (`NewBlockBuilderFidelityTests`, `ProgramViewFidelityTests`, `AdaptiveColorSourceTests`); every step that touches that file runs them.
"Verify" after a suite means the suite references a changed symbol or string and the step must run it, even if no edit is expected.
Acceptance for every step includes 17e light and dark captures of each state the step touches, added to `docs/design-map/screens/img/`, from the DEBUG seeds the step names.
