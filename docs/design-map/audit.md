# Audit

Every problem the map found in the app as built at commit `61353088`, with one row for each problem.
The screen writers, the workflow writers, the iPhone 17 Pro Max reviewers and the screenshot tour found them, and a problem that several of them saw has one row.
Rows are sorted by severity, then by screen.
A `blocker` stops a lifter from finishing a job or loses data, and a `major` problem makes a job much harder or breaks a design rule that most lifters notice.
A `minor` problem is a visible flaw with a workaround, and a `polish` problem is a small visual or copy flaw.
A problem that an open ticket already covers has one row that links the ticket, and the ticket describes it.
"(from code)" marks a problem read in the code and not seen on a phone.
A screenshot link opens the capture, and a backticked path and line points at the code or at the screen's accessibility tree.
[Patterns](#patterns) after the table groups the rows that break one design-system rule, with the one fix for each.

## Patterns

### P-1 A failed save or load is silent or unreadable

- Rule: The error state is a message in words next to the cause, and the blocked action stays visible, [interaction.md, Control states](../design-system/interaction.md#control-states).
- Rows (9): [D-08](#d-08), [D-20](#d-20), [D-59](#d-59), [D-153](#d-153), [D-155](#d-155), [D-189](#d-189), [D-216](#d-216), [D-231](#d-231), [D-292](#d-292).
- Fix: Route every save through one helper that catches the error and shows a plain-language alert naming what was not saved, instead of `try?` or the system's error text.

### P-2 Touch targets under 44 pt

- Rule: Every tappable element has a hit area of at least 44 by 44 pt, [interaction.md, Touch targets](../design-system/interaction.md#touch-targets).
- Rows (18): [D-05](#d-05), [D-16](#d-16), [D-35](#d-35), [D-37](#d-37), [D-50](#d-50), [D-67](#d-67), [D-99](#d-99), [D-103](#d-103), [D-113](#d-113), [D-117](#d-117), [D-118](#d-118), [D-148](#d-148), [D-160](#d-160), [D-168](#d-168), [D-174](#d-174), [D-181](#d-181), [D-185](#d-185), [D-293](#d-293).
- Fix: Give the shared chip and filter components (`ProgressFilterChip`, the New Block chips, the plate chips) a 44 pt floor and put `.bruHitArea()` on small text buttons, rather than padding each screen.

### P-3 Logged workouts and sessions called by the wrong word

- Rule: No design-system section states the copy words; the map's rule is that a logged workout is a workout, a session is the plan and a routine bundles sessions, [conventions.md, Words](conventions.md#words).
- Rows (23): [D-34](#d-34), [D-61](#d-61), [D-200](#d-200), [D-204](#d-204), [D-220](#d-220), [D-232](#d-232), [D-241](#d-241), [D-249](#d-249), [D-250](#d-250), [D-252](#d-252), [D-257](#d-257), [D-268](#d-268), [D-291](#d-291), [D-296](#d-296), [D-307](#d-307), [D-308](#d-308), [D-309](#d-309), [D-326](#d-326), [D-339](#d-339), [D-341](#d-341), [D-348](#d-348), [D-355](#d-355), [D-362](#d-362).
- Fix: Run one copy sweep over the user-facing strings with the Words table as the source, as the open copy-sweep ticket T34 (done) plans.

### P-4 Text breaks inside words or numbers at large text

- Rule: Components change layout at accessibility sizes instead of truncating, and every screen works up to AX3 at 390 pt with no clipped text, [accessibility.md, Dynamic Type](../design-system/accessibility.md#dynamic-type).
- Rows (14): [D-07](#d-07), [D-36](#d-36), [D-42](#d-42), [D-65](#d-65), [D-113](#d-113), [D-133](#d-133), [D-137](#d-137), [D-167](#d-167), [D-178](#d-178), [D-194](#d-194), [D-243](#d-243), [D-295](#d-295), [D-318](#d-318), [D-345](#d-345).
- Fix: Stack fixed-width columns at accessibility sizes, join numbers to their units with non-breaking spaces, and give single-word labels `.lineLimit(1)` with a minimum scale factor.

### P-5 Fixed sheet heights and fixed bars hide content at AX3

- Rule: Every screen must work up to AX3 with no clipped text, [accessibility.md, Dynamic Type](../design-system/accessibility.md#dynamic-type), and fixed chrome grows only when Dynamic Type makes its labels taller, [layout.md, Fixed chrome](../design-system/layout.md#fixed-chrome).
- Rows (12): [D-10](#d-10), [D-23](#d-23), [D-29](#d-29), [D-36](#d-36), [D-41](#d-41), [D-78](#d-78), [D-87](#d-87), [D-98](#d-98), [D-113](#d-113), [D-143](#d-143), [D-211](#d-211), [D-287](#d-287).
- Fix: Let sheets open at the large detent at accessibility sizes, as the rest sheet already does, and let pinned bars scroll with the content when the text size is large.

### P-6 Bright signal fill used as small text

- Rule: The bright `bruSignal` fill is never small text on paper; text uses its readable foreground variant, [color.md, Rules](../design-system/color.md#rules).
- Rows (8): [D-38](#d-38), [D-46](#d-46), [D-76](#d-76), [D-120](#d-120), [D-138](#d-138), [D-139](#d-139), [D-147](#d-147), [D-313](#d-313).
- Fix: Replace `bruSignal` with `bruSignalText` wherever it colors text, and add the token to the BRU grep audit tests so it cannot return.

### P-7 More than one signal element on a screen

- Rule: The signal color marks the one primary action, completed sets, records and upward trends, and two signal elements never compete, [principles.md, One accent](../design-system/principles.md#2-one-accent-used-on-purpose).
- Rows (14): [D-43](#d-43), [D-75](#d-75), [D-126](#d-126), [D-170](#d-170), [D-210](#d-210), [D-240](#d-240), [D-248](#d-248), [D-253](#d-253), [D-261](#d-261), [D-267](#d-267), [D-282](#d-282), [D-319](#d-319), [D-324](#d-324), [D-357](#d-357).
- Fix: Use the ink fill for selected chips and tags and plain ink for header actions, keeping the signal fill for the screen's one forward action and for real records.

### P-8 Sheets with no close control, or closed different ways

- Rule: No design-system section states how a sheet closes; the closest is the header's `.cancel` action, [components.md, Chrome](../design-system/components.md#chrome).
- Rows (7): [D-05](#d-05), [D-63](#d-63), [D-102](#d-102), [D-123](#d-123), [D-141](#d-141), [D-149](#d-149), [D-151](#d-151).
- Fix: Decide one close control for sheets, a CANCEL in the header's left slot, and use it on every sheet.

### P-9 Confirmations that do not follow the confirmation rule

- Rule: A destructive action asks once, names the consequence, uses the verb on its button and keeps Cancel available, [interaction.md, Confirmation](../design-system/interaction.md#confirmation).
- Rows (10): [D-56](#d-56), [D-154](#d-154), [D-214](#d-214), [D-219](#d-219), [D-222](#d-222), [D-223](#d-223), [D-227](#d-227), [D-228](#d-228), [D-235](#d-235), [D-337](#d-337).
- Fix: Write one confirmation template (title, consequence message, verb button, one cancel form) and build every destructive dialog from it.

### P-10 System controls where BRU has its own

- Rule: BRU screens use no system `Stepper` or system toggle styling, and BRU components replace each such control, such as `BRUActionPopover` for `confirmationDialog` menus, [principles.md, System chrome stays out](../design-system/principles.md#7-system-chrome-stays-out).
  Feature code never uses system colors, [color.md, Rules](../design-system/color.md#rules).
- Rows (6): [D-108](#d-108), [D-172](#d-172), [D-184](#d-184), [D-199](#d-199), [D-234](#d-234), [D-270](#d-270).
- Fix: Switch these to `BRUToggleStyle`, `BRUStepper` inside the shared target stepper, `BRUActionPopover` and BRU tokens, and extend the banned-API grep tests to cover them.

### P-11 Static text styled as a control

- Rule: No design-system section states that only controls may look tappable; the closest is the control-state table, [interaction.md, Control states](../design-system/interaction.md#control-states).
- Rows (9): [D-45](#d-45), [D-113](#d-113), [D-175](#d-175), [D-192](#d-192), [D-290](#d-290), [D-301](#d-301), [D-312](#d-312), [D-325](#d-325), [D-361](#d-361).
- Fix: Either wire each of these to a real action or restyle it as plain muted text with no action styling, chevron or border.

### P-12 Empty states without a headline or a fixing action

- Rule: An empty state shows a condensed headline, one sentence of help and one action that fixes it, [interaction.md, Control states](../design-system/interaction.md#control-states).
- Rows (6): [D-05](#d-05), [D-83](#d-83), [D-191](#d-191), [D-300](#d-300), [D-310](#d-310), [D-353](#d-353).
- Fix: Build these from one shared empty-state view with headline, help line and action, as Library, history and Program already do.
