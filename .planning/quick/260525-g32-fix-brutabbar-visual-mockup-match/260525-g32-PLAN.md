<design_decision>
Rather than hard-coding `Color.white` / `Color.black` (which would break dark-mode
adaptivity) or repurposing `bruPaper`/`bruHair` (which would change every other
surface in the app), we introduce two NEW adaptive tokens dedicated to the tab
bar chrome:

  - `bruTabSurface`     light: pure white (1.000, 1.000, 1.000)
                        dark : near-black, matches bruInk dark (0.039, 0.039, 0.039)

  - `bruTabSeparator`   light: structural neutral gray (0.85, 0.85, 0.85) — cool, not beige
                        dark : mid-gray (0.27, 0.27, 0.27)

Active cell stays on `Color.bruInk` (already near-black in light / near-white
in dark) — no new token needed and the inversion behavior is the same as
`bruTabSurface`, so the contrast pair is preserved in both modes.

Foreground on the active cell flips to `Color.bruTabSurface` so the active-on-active
contrast pair inverts correctly: in light mode bruInk fills near-black and
bruTabSurface text is pure white; in dark mode bruInk fills near-white and
bruTabSurface text is near-black. Same pattern for inactive cells (bruTabSurface
fill, bruInk text). The contrast direction flips with the system appearance.
</design_decision>
