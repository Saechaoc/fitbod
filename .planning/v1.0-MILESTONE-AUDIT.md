## Cross-Phase Integration Warnings (5)

### INT-W1 — BlockCard "End Block" orphans review path (BLOCK-06)
**File:** `fitbod/Periodization/BlockCard.swift:38-50`
Manual "End block" sets `isActive=false` directly, bypassing `BlockReviewStatistics.acknowledge(...)`. Alert copy says "You can review it from the Routines tab" but no such entry point exists — only the Today-tab pendingReviewBlocks query, which requires `isActive==true`. Once manually ended, the block is unreachable for review.

**Fix:** Either route "End Block" through `acknowledge()` (sets `reviewedAt`) OR add a Routines-tab review entry point for past-ended blocks. Defer to v1.1 polish.

### INT-W2 — BlockPickerMenu sheet missing NavigationStack
**File:** `fitbod/Periodization/BlockPickerMenu.swift:60-62`
Presents `BlockBuilderView` without NavigationStack wrap. View's `.navigationTitle` + `.toolbar { Cancel; Save }` won't render. User taps "+ Create New Block" → sheet appears with no nav bar / no Cancel / no Save.

**Fix:** Wrap in NavigationStack like the 4 other call sites. Trivial.

### INT-W3 — Orphan file ConsiderDeloadBanner.swift
**File:** `fitbod/Periodization/ConsiderDeloadBanner.swift`
Phase 4 stub superseded by Phase 5 `DeloadAdvisoryBanner`. Zero production call sites.

**Fix:** Delete or document as intentional alternative impl.

### INT-W4 — Duplicate snapshot logic (BackupArchiver vs ExportService)
**Files:** `fitbod/Backup/BackupArchiver.swift:145-176` + `fitbod/Export/ExportService.swift:67-98`
Both build `ExportDocument` from per-entity fetches. Documented as intentional due to cross-`@ModelActor` cost. Future-add-field risk: if a new field lands in only one snapshot, backups silently drop the field.

**Fix:** Extract shared snapshot helper OR add a regression test that mirrors the two builders.

### INT-W5 — Stale test doc comment
**File:** `fitbodTests/RoutineBuilderHeaderPickersTests.swift:51`
Comment references "V4 ModelContext over Schema(SchemaV5.models)" — schema bumped to V6 in Phase 5.

**Fix:** Update comment. Trivial.
