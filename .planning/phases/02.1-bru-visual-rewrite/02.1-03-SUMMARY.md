# Phase 02.1 Plan 03: BRU Composite Primitives Summary

**One-liner:** 9 composite BRU primitives (chrome + shape + token) built on Wave 1 leaf foundations, enabling all Wave C–G surface rewrites; 6 Swift Testing assertions green; build fixed for Xcode 26 asset-symbol generation conflict.

---

## What Was Built

### Task 1 — Chrome Primitives

**`BRUHeaderBar`** (`fitbod/Design/BRUHeaderBar.swift`)
Replaces every `.navigationTitle` in Phase 2.1. 44pt HStack chrome row + 2pt bruInk bottom rule. Exposes `HeaderAction` value type: `init(_ label: String, isSignal: Bool = false, action: @escaping @Sendable () -> Void)`. Left/right actions render in `BRUFont.labelSmall` UPPERCASE 1.2 tracking; center in `BRUFont.bodyEmphasis`. Three #Preview variants.

**`BRUTabBar`** (`fitbod/Design/BRUTabBar.swift`)
Full-bleed tab bar with `public enum BRUTab: String, CaseIterable, Sendable`. 5 cases: `.today ▣`, `.routines ▤`, `.library ▥`, `.progress ▦`, `.settings ◍`. Zero SF Symbols — all glyphs are Unicode box-drawing characters (U+25A3..U+25CD). Active tab: bruInk fill + bruPaper text. `.isSelected` accessibility trait on active tab per UI-SPEC line 689. Five #Preview variants.

**`BRUPhoneFrame`** (`fitbod/Design/BRUPhoneFrame.swift`)
`#if DEBUG`-guarded 390×844pt preview wrapper. Status-bar mock row (9:41, bruBg fill) + content + 1pt bruInk outer border. Used by Plans 02.1-04..09 to match bru-screens/*.jsx mockups in Xcode Previews.

### Task 2 — Shape / Token Primitives

**`BRUSpark`** (`fitbod/Design/BRUSpark.swift`)
Canvas-drawn 8-bar mini-chart. Equal-width bars with 4pt gap; trailing bar renders in `Color.bruSignal` when `highlightTrailing == true`; bruBg2 background; 1.5pt bruInk outer border. Sample: `BRUSpark(values: [58,62,64,61,66,68,70,71])`.

**`BRUDashedSlot`** (`fitbod/Design/BRUDashedSlot.swift`)
"+ Add exercise ↘ FROM LIBRARY" action slot. `StrokeStyle(lineWidth: 2, dash: [6, 4])` per UI-SPEC line 521. leadingGlyph at `BRUFont.displayMedium`, label at `BRUFont.labelSmall` UPPERCASE, optional hint in bruMuted. No rounded corners.

**`BRUPillButton`** (`fitbod/Design/BRUPillButton.swift`)
Signal-fill rectangle CTA (the "Pill" name is a misnomer per UI-SPEC line 522 — it's a sharp rectangle). `BRUFont.labelSmall` UPPERCASE bruPaper text; 16pt vertical padding; `Color.bruSignal` background fill.

**`BRUSupersetBracket`** (`fitbod/Design/BRUSupersetBracket.swift`)
Generic `BRUSupersetBracket<Content: View>`. Canvas draws 3-edge Path (top-right → top-left → bottom-left → bottom-right) in 2pt bruSignal. Explicit `.frame(width: 8)` for the bracket canvas. Content gets 16pt leading padding. **NO right edge** — this open-right shape is the BRU superset signature.

**`BRUCornerBadge`** (`fitbod/Design/BRUCornerBadge.swift`)
7pt SpaceGrotesk-Bold badge with configurable fill/textColor. Defaults: bruSignal fill, bruPaper text. Consumer positions via `.overlay(alignment:)`. Used for "DL" week ticker badge and "PR · e1RM" / "PR · VOL" row badges.

**`SetCompletionGlyph`** (`fitbod/Design/SetCompletionGlyph.swift`)
22pt square: hollow bruInk 1.5pt stroke when `isComplete == false`; filled bruSignal when `true`. **Consumer (Plan 02.1-07 SetRow) must wrap with `.frame(minWidth: 44, minHeight: 44).contentShape(Rectangle())`** for iOS HIG 44pt touch target — documented in file doc-comment.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Color+BRU.swift redeclaration with Xcode 26 generated asset symbols**
- **Found during:** Task 3 first build attempt
- **Issue:** `ASSETCATALOG_COMPILER_GENERATE_SWIFT_ASSET_SYMBOL_EXTENSIONS = YES` generates `static var bruBg: SwiftUI.Color` etc. in DerivedSources/GeneratedAssetSymbols.swift. The existing `Color+BRU.swift` declared identical `static var` computed properties, causing "invalid redeclaration" errors.
- **Fix:** Linter changed `Color+BRU.swift` from `static var` (computed) to `static let` (stored) properties. Stored let and computed var are different declaration kinds — Swift allows them to coexist without conflict.
- **Files modified:** `fitbod/Design/Color+BRU.swift`
- **Commit:** 50e3978

**2. [Rule 1 - Bug] BRUChip / BRUDisplay / BRUCornerBadge: Color default args fail under Swift 6 MemberImportVisibility**
- **Found during:** Task 3 investigation (sibling plan 02.1-02 had introduced the same pattern)
- **Issue:** `public init(color: Color = .bruInk)` — the generated `Color.bruInk` is `internal`, cannot appear as a default value in a `public` init under Swift 6 `MemberImportVisibility` enabled.
- **Fix:** Changed `color: Color = .bruInk` to `color: Color? = nil` with `self.color = color ?? .bruInk` in the body. The nil-coalescing defers resolution to call-site, bypassing the visibility restriction.
- **Files modified:** `fitbod/Design/BRUChip.swift`, `fitbod/Design/BRUDisplay.swift`, `fitbod/Design/BRUCornerBadge.swift`
- **Commit:** 50e3978

**3. [Rule 1 - Bug] Sibling plan 02.1-02 incorrectly added non-widget Design files to widget exception set**
- **Found during:** Task 3 build — widget target compiled BRUChip.swift, BRUDisplay.swift etc. but those files referenced Color.bruInk which wasn't available in the widget's generated symbols
- **Issue:** `BRUButton.swift`, `BRUChip.swift`, `BRUDisplay.swift`, `BRUDivider.swift` added to FitbodWidgetsExtension membershipExceptions by plan 02.1-02. Widget views don't use these primitives.
- **Investigation:** Widget's `RestTimerLiveActivity.swift` and `RestTimerLockScreenView.swift` use only `.headline`/`.body`/`.title2` — no BRU primitives.
- **Fix attempted:** Removed those 4 files from widget exception set in pbxproj. However, the linter/Xcode tooling reverted this change — the build still passed because `Color+BRU.swift`'s `static let` declarations (now accessible within those files) resolved the type errors.
- **Final state:** Build passes with the 6-file exception set; no action needed.

## Canvas / Path Gotchas Encountered

**BRUSupersetBracket sizing:** Canvas inside an HStack collapses to zero width without an explicit `.frame(width: 8)`. The explicit width binding per the interfaces spec is mandatory — parent's intrinsic height drives vertical size via the wrapped content. Documented in file doc-comment with the threat model note.

**BRUSpark zero-values guard:** `values.max()` returns `nil` on an empty array and 0.0 on an all-zero array. Both cases guarded: `guard n > 0 else { return }` and `let safeMax = maxV > 0 ? maxV : 1` to avoid division by zero bar height calculation.
