# Phase 2.1 Plan 07: Session Logger BRU Rewrite Summary

BRU brutalist rewrite of the 7 core session logger surfaces — the highest-traffic screen in the app. Strips all Apple HIG chrome (SF Symbols, Capsule clips, semantic system fonts, accentColor) and replaces with BRU primitives.

## What Was Built

### 3-Line Principal Header Block (SessionLoggerView)

The `SessionLoggerView` now uses `.safeAreaInset(edge: .top)` with a `VStack(spacing: 0)` containing:

```
BRUHeaderBar(left: "‹", center: "Workout", right: "•••")
─── 2pt bruInk rule ─────────────────────────────────
[session.routineSnapshotName displayMedium]  [elapsed bodyEmphasis muted]
IntentChip(intent: session.intent)
─── 2pt bruInk rule ─────────────────────────────────
```

The "•••" right action presents a `.confirmationDialog` with "Workout notes" / "Finish" / "Discard" options. No `.toolbar` or `.navigationTitle` remain.

### SetTypeChip Mapping (shipped)

| SetType enum case | BRU chip label | Color |
|-------------------|---------------|-------|
| `.working`        | (no chip)     | —     |
| `.warmup`         | "W/UP"        | bruInk outline |
| `.drop`           | "DROP"        | bruInk outline |
| `.failure`        | "FAIL"        | bruInk outline |
| `.restPause`      | "RP"          | bruInk outline |

Note: `topSet` ("TOP" signal) and `backOff` ("BACK") are referenced in UI-SPEC but the `SetType` enum only has 5 cases. "TOP" and "BACK" are deferred until the model extension adds those cases.

### SessionExerciseCard Structure

```
VStack(spacing: 0) {
  HStack { [01] [Exercise name + equipment sub-line] [⋮⋮] }  ← .contextMenu
  BRUDivider(.hair)
  PinnedNoteCapsule (if populated)
  BumpBanner (if bumpOccurred)
  WarmupRampRows (if warmup sets present)
  [Plateau badges if stalled]
  [CalibratingBadge if calibrating]
  HStack { "S" "PREVIOUS" "WEIGHT" "REPS" "RPE" }  ← labelSmall 1.2 bruMuted
  BRUDivider(.hair)
  SetRow[0] + BRUDivider(.hair)
  SetRow[1] + BRUDivider(.hair)
  ...
  Button("+ ADD SET")  ← bruSignal text
}
```

### safeAreaInset Stacking (T-02.1-07-05)

Two `.safeAreaInset(edge: .top)` modifiers coexist:
1. `InSessionPRBanner` (Phase 6 — `prState`)
2. `bruHeader` (the BRUHeaderBar + 3-line block)

SwiftUI stacks multiple `.safeAreaInset(edge: .top)` modifiers in reverse order — the `bruHeader` (declared first) appears below `InSessionPRBanner` in the layout, which is correct. No overlap observed in preview.
