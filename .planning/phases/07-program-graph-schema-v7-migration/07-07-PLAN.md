Close the three verified gaps blocking Phase 7 from passing its named deliverable
("SchemaV7MigrationTests green"). All three are real defects, not test contamination:

1. **Nullify delete-rules not wired (spec §3).** `Session.slot` and the legacy
   `SessionTemplate.block` are plain `var`s with no managed inverse, so SwiftData
   never nullifies them on source deletion. Two tests fail
   (`slotNullifyHistoryIntact`, `BlocksSectionTests.deletingBlockNullifiesRoutineLink`).

   templates because the test container registers only `SchemaV7.models` (which does
   NOT include the `SchemaV6.Routine` nested type the stash fetches), so seeded rows
   never persist. `templateNameBackfill` is order-dependent because the static stash
   leaks between tests. `SchemaV6MigrationTests` uses a wrong `+2` count arithmetic.

   fitbod.SessionTemplate`, so a V5 store's `Routine`/`RoutineExercise` entity names
   no longer resolve — the identical CR-01 break the reviewer fixed for V1/V2.

Purpose: make the phase's exit gate green and deterministic so Phase 8 can proceed.

count-pin, and a walkable V5 schema — with V1/V2/V4/V6 suites kept green.
