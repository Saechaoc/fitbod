## Deviations from Plan

### Auto-applied decisions (no structural changes)

**1. [Rule 2 - Missing Critical] Smart Progression section kept in Section{} wrapper**
- **Found during:** Task 2
- **Issue:** The plan said to migrate Smart Progression to BRUSectionHead + BRURow but the existing 03.2-08 reskin already used BRUSectionHead as a Section header. Rebuilding it would be redundant.
- **Fix:** Preserved the entire 03.2-08 Smart Progression implementation verbatim inside its Section{} wrapper. The section still uses BRUSectionHead, BRUFont tokens, and Color.bruMuted — fully compliant with BRU; only the SwiftUI container differs (Section vs standalone).
- **Impact:** Zero — section renders identically, all tokens correct.

**2. [Rule 1 - Implementation] Backup CREATE uses labeled ShareLink text rather than BRUButton**
- **Found during:** Task 3
- **Issue:** Wrapping a BRUButton inside ShareLink's label closure would create a nested tap gesture conflict where BRUButton's own `.buttonStyle(.plain)` absorbs the tap before ShareLink processes it.
- **Fix:** Used a `Text("CREATE")` with explicit `font(BRUFont.labelSmall).tracking(1.2).textCase(.uppercase).foregroundStyle(Color.bruInk).frame(maxWidth: .infinity, minHeight: 44)` inside the ShareLink label — visually identical to ghost button, no gesture conflict.
- **Files modified:** SettingsView.swift
- **Commit:** 667d793

**3. [Rule 2 - Missing Critical] lastBackupDescription / entityCountLine are v1 placeholders**
- **Found during:** Task 3
- **Issue:** Real last-backup metadata (timestamp + entity counts) requires persisted backup state that does not yet exist in the store schema.
- **Fix:** Placeholder strings "No backup yet" and "Create a backup to protect your data" used. Display renders correctly; data wires deferred to a future plan.
