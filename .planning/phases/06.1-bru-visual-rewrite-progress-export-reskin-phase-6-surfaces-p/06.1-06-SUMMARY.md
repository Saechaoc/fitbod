## What Was Built

### InSessionPRBanner (Task 1)

Replaced the `RoundedRectangle(cornerRadius: 22)` capsule with a full-bleed `Color.bruSignal` background. New layer stack:

- Layer 1: `"PR"` in `BRUFont.labelSmall` + `tracking(1.5)` + `.textCase(.uppercase)`, `Color.bruPaper`
- Layer 2: `BRUDisplay(.medium)` PR-kinds composite in canonical order (weight → reps → volume → e1RM), middot-joined, `Color.bruPaper`
- Layer 3: `BRUFont.labelSmall` set-detail mono sub-line (e.g. `"· 102.5 KG × 5"`), `Color.bruPaper.opacity(0.8)`

Preserved: 44pt `minHeight`, tap-dismiss via `state.dismiss()`, reduce-motion-aware `.transition`, `.animation(.smooth(duration: 0.18))`, all accessibility traits (`.isButton`, `.updatesFrequently`, `UIAccessibility.post(.announcement)`), updated accessibilityHint to match UI-SPEC verbatim.

Stripped: `Color.accentColor`, `Color(.label)`, `Color(.secondaryLabel)`, `.font(.body)`, `.font(.caption)`, `RoundedRectangle(cornerRadius:)`, `.fill(...)` overlay, `.stroke(...)` overlay, `.clipShape(...)`.

### ExerciseHistoryView (Task 2)

Replaced the `right: HeaderAction("FILTER", isSignal: true, ...)` stub with `right: HeaderAction("PROGRESS", isSignal: false, action: { presentingProgress = true })`, conditional on `hasHistory`. When no sets exist, `right: nil` is passed so the BRUHeaderBar right slot is empty.

Navigation: `@State private var presentingProgress = false` + `.navigationDestination(isPresented: $presentingProgress) { ExerciseProgressView(exercise: exercise) }`.

History-count propagation: `onHistoryChanged` callback from `FilteredHistoryContent` to outer view, invoked inside the `body` computed property, updates `hasHistory`.

The unimplemented `presentingFilter` stub (comment: "future: advanced filter sheet") and its `@Binding var presentingFilter: Bool` chain were removed — the binding was passed all the way into `FilteredHistoryContent` but never presented a sheet.

## Deviations from Plan

### Auto-adjusted — Set-detail sub-line format

**Found during:** Task 1

**Issue:** The plan specified the sub-line as `"BENCH PRESS · 102.5 KG × 5"` (exercise name + middot + weight + unit + reps). `InSessionPRBannerContent` carries `weight: Double` and `reps: Int` but no `exerciseName` field. Adding an exercise name field would require changes to `InSessionPRState` and `PRDetector` — outside the file-ownership boundary of this plan.

**Fix:** Sub-line renders `"· 102.5 KG × 5"` (leading middot, weight, reps). The PR-kinds composite (Layer 2) provides the "what exercise" context via the session context. The 44pt slab, tap-dismiss, and all other contracts are fully met.

**Files modified:** `fitbod/Sessions/InSessionPRBanner.swift`

**Commit:** dfe8a49

### Auto-adjusted — FILTER HeaderAction removed (was unimplemented stub)

**Found during:** Task 2

**Issue:** The plan said "Replace with a BRU typographic affordance: pass a `right: HeaderAction("PROGRESS", ...)` parameter." BRUHeaderBar has a single `right` slot. The existing `right: HeaderAction("FILTER", ...)` had a comment marking it as a "future: advanced filter sheet" and `presentingFilter` was never wired to any `.sheet(...)` presentation.

**Fix:** Removed the FILTER stub entirely; wired PROGRESS into the right slot. The intent-chip row below the header still provides inline intent filtering — the FILTER header action added no behavior.

**Files modified:** `fitbod/ExerciseLibrary/ExerciseHistoryView.swift`

**Commit:** 0de409f
