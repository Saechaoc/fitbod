# Phase 04.1: BRU Visual Rewrite (Periodization & Blocks) - Context

**Gathered:** 2026-05-23
**Status:** Ready for planning

<domain>
## Phase Boundary

Re-skin all Phase 4 (Periodization & Blocks) user-facing surfaces from Apple HIG defaults to the BRU brutalist design system defined in `04-UI-SPEC.md` v3 (atop the locked BRU primitives from `02-UI-SPEC.md`). Closes the systematic full-layer drift documented in `04-UI-REVIEW.md` (overall 9/24, 3 BLOCKERs).

Scope is bounded to:
- The 12 Phase-4-owned files audited (BlockBuilderView, BlockReviewView, BlockCard, BlockPhaseEditorRow, BlockRow, BlockPickerMenu, MesocycleWeekPage, DeloadWeekBanner, ConsiderDeloadBanner, StartBlockCTA, BlockPhaseColors, RoutinesListView.blocksSection).
- One net-new surface: `BlockOverviewScreen` (BRU mockup `block-overview.jsx` defines it; current code is absent — tapping `BlockCard` opens edit mode instead).
- Audit-flagged accessibility and reduced-motion fixes on those surfaces.

**Phase 4 functional behavior is preserved.** Block builder, scheduled deloads, block timeline, four progression strategies, and end-of-block review all keep their existing behavior — the audit is about visual layer + accessibility, not about feature regression.

**Out of scope:** `TodayView` block strip (owned by Phase 2.1), any Phase 5 surfaces (heatmap, volume bars), backlog warnings outside the 12 audited files, new Phase 4 functionality beyond `BlockOverviewScreen`.

</domain>

<decisions>
## Implementation Decisions

### Foundation Dependency
- **D-01:** Phase 04.1 **depends on Phase 2.1's foundation plan (`02.1-01-PLAN.md`)** for the shared BRU layer: 8 color tokens (`bruInk`, `bruPaper`, `bruSignal`, `bruFaint`, `bruHair`, `bruMuted`, `bruBg`, `bruBg2`), 4 OFL fonts (Space Grotesk Bold + SemiBold, JetBrains Mono Regular + Bold), `Color+BRU.swift`, `BRUFont.swift` 7-role enum, `Info.plist` `UIAppFonts` registration, `BRUFoundationsTests`. 04.1 plans **MUST NOT** duplicate any of this — they consume what `02.1-01` ships.
- **D-02:** Planner must record this in `Depends on:` for every 04.1 plan and update the ROADMAP entry for Phase 04.1 to read `**Depends on:** Phase 4, Phase 2.1 (specifically 02.1-01-PLAN.md foundation)`.
- **D-03:** If `02.1-01` has not been executed at the time `/gsd:execute-phase 04.1` runs, the executor halts with a clear "BRU foundation missing — run 02.1-01 first" message. The planner should encode this in Wave 0 verification (no `Color.bru*` extensions on disk → block).

### Surface Scope (all 12 Phase-4 surfaces — full BRU compliance)
- **D-04:** Every one of the 12 audited files is in scope. Partial re-skin is explicitly rejected — `04-UI-REVIEW.md` Verdict §1 frames the drift as systematic, so partial fix would leave visible inconsistency between blocks views.
- **D-05:** Re-skin replaces (not augments): every `Color.accentColor`, `Color.red`, `Color.yellow`, `Color(.system*)`, `Color(.secondarySystemGroupedBackground)`, every `RoundedRectangle(cornerRadius:)`, `Capsule()`, `Circle()` (where used as visual element, not chrome), and every `.font(.headline/.caption/.body/.title*)` call inside the 12 files must be replaced with BRU equivalents per `04-UI-SPEC.md` v3.
- **D-06:** `Form { Section { ... } }` Apple inset-grouped layout is replaced with `ScrollView` + `VStack` bodies in `BlockBuilderView` and `BlockReviewView` per `04-UI-REVIEW.md` Pillar 2 Fix 3.
- **D-07:** SF Symbol replacements (typographic glyphs) per `04-UI-REVIEW.md` Pillar 6 table: `line.3.horizontal` → `⋮⋮`, `ellipsis.circle` → `•••`, `exclamationmark.triangle` → `▲`, `xmark` → `BRUChip "DISMISS"` (or `×`), `chevron.right` → `›`. `trash` swipe-action stays (system chrome).
- **D-08:** `BlockPhaseColors.swift` D-07 pre-BRU palette (teal/amber/orange/slate) is replaced per the table in `04-UI-REVIEW.md` Pillar 3: accumulation → `bruInk`, intensification → `bruSignal`, realization → `bruInk.opacity(0.25)`, deload → diagonal-stripe `Canvas` pattern.
- **D-09:** Copy drift fixes (`04-UI-REVIEW.md` Pillar 1 WARNING table) are in scope: Blocks empty-state heading + body, "+ NEW BLOCK" signal text CTA (not `Menu("+ Block")`), `ConsiderDeloadBanner` "▲ FATIGUE ADVISORY" header, `BlockBuilderView` toolbar "Save" → primary `BRUButton "Apply changes ▸"`, `BlockReviewView` section header rewording per spec.

### BlockOverviewScreen (net-new surface)
- **D-10:** Build `BlockOverviewScreen` in `fitbod/Periodization/BlockOverviewScreen.swift` per `bru-screens/block-overview.jsx`. Composition: BRU header band → week carousel (W1..WN with DL badge) → phase progression list → fatigue advisory strip (only when `ConsiderDeloadBanner` would surface).
- **D-11:** Rewire `BlockCard` tap behavior: tap → push `BlockOverviewScreen` (read-only summary). `BlockOverviewScreen` exposes an explicit "EDIT BLOCK ▸" `BRUButton kind="primary"` that pushes `BlockBuilderView` in edit mode. This replaces the current tap → `BlockBuilderView` direct-edit behavior — a small behavior change justified by the spec view's absence being the audit's missing-screen finding.
- **D-12:** `BlockOverviewScreen` reads, never writes. All mutations stay in `BlockBuilderView`.

### Behavior Preservation Contract
- **D-13:** **Visual rewrite is primary.** Zero changes to PeriodizationEngine, MesocycleWeekContext, BlockDraft transactional save semantics, deload-week math, progression strategies, or any other Phase 4 behavior except those listed in D-11 (tap routing) and D-14..D-17 below.
- **D-14:** Fix audit-flagged reduced-motion gap on `BlockCard` `TabView(.page)` pager: wrap in `@Environment(\.accessibilityReduceMotion)` check; when reduced motion is true, snap-without-slide.
- **D-15:** Fix audit-flagged `accessibilityLabel` gaps: `BlockCard` (`"Active block: {name}, {phaseKind} phase, week {N} of {M}."`), `BlockPhaseEditorRow` (`"Phase {ordinal}: {kind}"`), and the new `BlockOverviewScreen` surfaces.
- **D-16:** Remove out-of-spec "Adjust block" button from `ConsiderDeloadBanner` (spec defines only header + body + dismiss).
- **D-17:** Wire `BRUChip "DISMISS"` as the dismiss affordance on `ConsiderDeloadBanner` (replaces `Image(systemName: "xmark")` button).
- **D-18:** **All existing Phase 4 functional tests must still pass.** No production behavior regression beyond D-11 / D-16 (both of which are intentional + traceable). Snapshot/visual tests for re-skinned surfaces are net-new additions, not replacements.
- **D-19** [informational]: Out of scope (audit findings explicitly deferred): copy-case rendering audit beyond the 12 files, single-active invariant copy audit beyond the listed warnings, any new fatigue/deload feature not already shipped in Phase 4 + Phase 5. Meta-rule (scope fence) — constrains all plans rather than mapping to a specific task; not tracked by the decision-coverage gate.

### Mockup-vs-Spec Source of Truth (Claude's Discretion)
- **D-20** [informational]: When `bru-screens/*.jsx` mockups and `04-UI-SPEC.md` v3 disagree, `04-UI-SPEC.md` v3 is the contract (it is the locked, reviewed artifact). Mockups are the pixel reference for values the spec defers (exact y-coordinates, sub-pixel borders, ordering inside a row). Pure-presentation deviations in the mockup that violate the spec's BRU rules (e.g., a hypothetical rounded corner in a mockup) are not authoritative. Meta-rule (precedence convention) — applies globally to every plan; not tracked by the decision-coverage gate.

### Claude's Discretion
- **D-21:** Plan-wave structure: planner decides (foundation availability check → color/font swap waves → component-rebuild waves → BlockOverviewScreen wave → test/audit wave). Recommend ≤7 plans.
- **D-22:** Whether to bundle BlockBuilderView and BlockReviewView rebuilds as one plan or two — planner's call based on file-size and task-coupling judgement, but BlockReviewView's hero-band rebuild is non-trivial and probably wants its own plan.
- **D-23:** Snapshot test framework choice (XCTest snapshot helper vs Swift Testing-compatible alternative). No project precedent forces either; Phase 2.1's plan can set the precedent if it ships first.

</decisions>

<specifics>
## Specific Ideas

- Use `Canvas` for the 56pt `BlockBuilderView` TIMELINE (`04-UI-REVIEW.md` Pillar 2 Fix 1): phase-proportional bars, ink-filled past, `bruSignal`-filled current, 25% opacity future, diagonal-stripe deload pattern.
- Use `GeometryReader` for the `BlockReviewView` e1RM progress bars (`bruInk` fill + `bruSignal` cursor mark) per `04-UI-REVIEW.md` Pillar 2 Fix 2.
- `BlockBuilderView` "Apply changes ▸" CTA is a `BRUButton kind="primary"` in the body footer — replaces the toolbar "Save" button.
- `BlockReviewView` "Start next ▸" CTA is `BRUButton kind="signal"`.
- `BlockOverviewScreen` "EDIT BLOCK ▸" CTA is `BRUButton kind="primary"`.
- All `labelSmall` text gets `.textCase(.uppercase)` per `04-UI-REVIEW.md` Pillar 1.
- `DeloadWeekBanner` and `ConsiderDeloadBanner` use sharp 0-radius corners with 2pt `bruInk` top border on `bruBg2` background (no `RoundedRectangle`).
- BRU spacing values only: `{4, 8, 12, 16, 24, 32, 48, 64}`. The audit-flagged `spacing: 10` in `BlockPhaseEditorRow` and `padding(.vertical, 6)` must be replaced with in-set values.

</specifics>
