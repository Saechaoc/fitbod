## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] HeaderSlot.none renamed to HeaderSlot.empty**
- **Found during:** Task 2 (BRUHeaderBar.swift)
- **Issue:** `HeaderSlot.none` case collided with `Optional.none` — the Swift compiler could not determine exhaustiveness when switching on `HeaderSlot?` because `.none` was ambiguous between `HeaderSlot.none` and `Optional.none`
- **Fix:** Renamed `HeaderSlot.none` to `HeaderSlot.empty`; updated switch case from `case .none, nil:` to `case .empty, nil:`; updated test file accordingly
- **Files modified:** fitbod/Design/BRUHeaderBar.swift, fitbodTests/BRUPrimitivesTests.swift
- **Commit:** 1e9b8e6 (primitive) / 16180f0 (test)

**2. [Rule 3 - Blocking] BRUHeaderBar.slots() static factory replaces overloaded init**
- **Found during:** Task 2 (BRUHeaderBar.swift)
- **Issue:** Adding a second `init(left: HeaderSlot?, center: String?, right: HeaderSlot?)` alongside the existing `init(left: HeaderAction?, center: String?, right: HeaderAction?)` produced "ambiguous use of 'init(left:center:right:)'" because both inits have identical external labels and nil-defaulted params — Swift cannot distinguish `BRUHeaderBar(center: "Title")` between them
- **Fix:** Changed the HeaderSlot-based init to a private `init(slotLeft:center:slotRight:)` (distinct labels) plus a public `static func slots(left:center:right:)` factory. Plan's `<interfaces>` block specified `init(left: HeaderSlot?, ...)` — the factory achieves identical ergonomics (`BRUHeaderBar.slots(left: .back, ...)`)
- **Files modified:** fitbod/Design/BRUHeaderBar.swift
- **Commit:** 1e9b8e6

**3. [Rule 1 - Bug] bruButtonCallShapeCompiles test assertion updated for shorthand color refs**
- **Found during:** Task 4 (BRUPrimitivesTests.swift)
- **Issue:** `#expect(source.contains("Color.bruInk"))` failed because BRUButton.swift uses shorthand `.bruInk` in computed properties (`fileprivate var fillColor: Color { switch self { case .primary: return .bruInk ... } }`) without the `Color.` prefix
- **Fix:** Changed positive color assertions in bruButtonCallShapeCompiles to `source.contains("Color.bruInk") || source.contains(".bruInk")` pattern. Applied same OR pattern to bruSignal and bruPaper assertions
- **Files modified:** fitbodTests/BRUPrimitivesTests.swift
- **Commit:** feca3c7

**4. [Rule 1 - Bug] loadCodeOnly() helper added for forbidden-shape false positive**
- **Found during:** Task 3/4 (BRUPrimitivesTests.swift)
- **Issue:** `#expect(!source.contains("Capsule()"))` failed in bruChipCallShapeCompiles because BRUChip.swift's file header contains `// BRU contract: NO Capsule() / NO RoundedRectangle` — the prohibition documentation mentioned the prohibited patterns
- **Fix:** Added `loadCodeOnly(for:)` helper that strips all `//` single-line comment lines before running forbidden-shape assertions. The allPrimitivesAvoidForbiddenShapes test also uses this approach inline
- **Files modified:** fitbodTests/BRUPrimitivesTests.swift
- **Commit:** 16180f0
