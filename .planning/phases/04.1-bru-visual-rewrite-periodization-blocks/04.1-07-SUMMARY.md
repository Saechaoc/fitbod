`fitbod/Periodization/BlockOverviewScreen.swift` — 629 lines.

**6-band composition per 04.1-PATTERNS.md File #13 + bru-screens/block-overview.jsx:**

1. `BRUHeaderBar.slots(left: .back, center: "Block · <name>", right: .action("EDIT", onEdit))`

3. **Week carousel** — `@Query<Session>` backed, zero hardcoded mocks. ISO week boundaries computed in init:
   ```swift
   _weekSessions = Query(
       filter: #Predicate<Session> { session in
           session.startedAt >= startBound && session.startedAt < endBound
       },
       sort: [SortDescriptor(\Session.startedAt)]
   )
   ```
   Per-day state via `internal func dayState(for cellDate: Date) -> DayState`:
   - `.today` — `Calendar.current.isDate(cellDate, inSameDayAs: Date.now)`
   - `.done` — session in weekSessions matched to block (block.id or sourceRoutineID) + same day
   - `.upcoming` — future + routines exist
   - `.rest` — everything else

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] BlockCard not called from TodayView — wired BlockContextBand instead**
- **Found during:** Task 2 investigation
- **Issue:** The plan referenced "RootView.TodayView's BlockCard call site at line 310" but TodayView was extracted post-Phase 2.1 and now uses `BlockContextBand` (not `BlockCard`) for the Today-tab block display. `BlockCard` has zero production call sites.
- **Fix:** Added `onTap: (() -> Void)? = nil` to `BlockContextBand` and wired it from TodayView. `BlockCard`'s `onTapBlock` closure is still added (any future caller gets the routing behavior), but the live Today-tab wiring routes through `BlockContextBand.onTap`.
- **Files modified:** `fitbod/Views/BlockContextBand.swift`, `fitbod/Views/TodayView.swift`
- **Commit:** baaa355

**2. [Rule 1 - Bug] DayState enum private → internal for testability**
- **Found during:** Task 4 test authoring
- **Issue:** `DayState` was `private` but `dayState(for:)` was marked `internal` — Swift rejected this as "method cannot be declared internal because its result uses a private type"
- **Fix:** Promoted `DayState` to `internal` so `@testable import fitbod` test code can use the type.
- **Files modified:** `fitbod/Periodization/BlockOverviewScreen.swift`
- **Commit:** 9a1f3b1

**3. [Rule 1 - Bug] @Sendable on onEdit closure**
- **Found during:** Task 1 build check
- **Issue:** Swift 6 strict concurrency: "converting non-Sendable function value to '@Sendable () -> Void' may introduce data races"
- **Fix:** `public init(block: Block, onEdit: @escaping @Sendable () -> Void = {})` + stored property typed as `@Sendable () -> Void`
- **Files modified:** `fitbod/Periodization/BlockOverviewScreen.swift`
- **Commit:** 9a1f3b1

**4. [Rule 3 - Deviation] PendingBlockBuilder.edit case was missing**
- **Found during:** Task 2 TodayView wiring
- **Issue:** The plan referenced `.edit(Block)` case in `PendingBlockBuilder` enum but it did not exist — the enum only had `.template(BlockTemplate)`.
- **Fix:** Added `case edit(Block)` + `.sheet` handler for it per plan spec.
- **Files modified:** `fitbod/Views/TodayView.swift`
- **Commit:** baaa355
