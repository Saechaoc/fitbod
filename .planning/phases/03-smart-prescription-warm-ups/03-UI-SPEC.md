# Phase 3 — UI Design Contract

> Visual and interaction contract for Smart Prescription & Warm-ups. Generated by gsd-ui-researcher. **v2: BRU visual layer (2026-05-23)** — replaces the v1 Apple HIG styling with the brutalist design system used across all `bru-screens/*.jsx` mockups.

This phase makes each working set's recommended weight **transparent and inspectable**. The primary new surfaces are: a prescribed-weight cell with a signal-colored `●` status indicator on every working `SetRow`; a `WhyThisWeightSheet` (the `why-weight.jsx` mockup — a numbered-step disclosure showing the calculation breakdown: last session → target computation → plate rounding); an inline `PlateStackDisclosure` beneath each tapped weight cell (the plate-stack viz from `plate-calc.jsx`); a "You earned the weight bump" slab banner; a calibrating-progress meter on exercises with fewer than `minCalibrationSets` working sets; a 4-set warm-up ramp that auto-inserts as warm-up rows on the first qualifying compound (the warm-up ramp table shown in `why-weight.jsx`); and a `PlateInventoryEditor` reachable from Settings.

The design stance is **brutalist functional** — the same contract as Phase 02. All Phase 02 BRU tokens (ink/paper/signal/faint/hair/muted/bg/bg2), both font faces (Space Grotesk Bold + JetBrains Mono), all 6 type roles, all border widths, and all primitive components (`BRUChip`, `BRUDisplay`, `BRURReadout`, `BRUSectionHead`, `BRUButton`, `BRUDivider`, `BRUHeaderBar`, `BRUFont`) are inherited and used without modification. Phase 03 does not introduce a new design system — it extends Phase 02's.

## Spacing Scale

**Inherited verbatim from Phase 02.** Multiples of 4, iOS 8-point grid. BRU's brutalism does not change spacing primitives. Phase 03 usages added below.

| Token | Value | Phase 03 usage |
|-------|-------|----------------|
| xs | 4pt | Gap between plate rectangles in `PlateStackViz`; gap between set-index chip and weight value in `WarmupRampRow`; gap between tally-mark boxes in `PlateTallyRow`; gap between the `●` signal dot and "RECOMMENDED · RPE AUTOREG" label in `WhyThisWeightSheet` hero |
| sm | 8pt | Vertical gap between numbered steps in `WhyThisWeightSheet`; gap between the mini plate viz and the plate legend in `WarmupRampRow`; gap between "CALIBRATING · 8 / 10 SETS" label and the progress bar in `CalibratingProgressMeter`; padding inside `BumpBannerSlab` content |
| md | 12pt | Vertical padding of `WarmupRampRow` (matches `SetRow`); internal content padding inside `WhyThisWeightSheet` step blocks; `PlateInventoryEditor` row vertical padding; top margin before the calibration meter inside `WhyThisWeightSheet` |
| lg | 16pt | Horizontal screen inset for `WhyThisWeightSheet`, `PlateInventoryEditor`, `PlateCalculatorSheet`; padding inside the ink hero slab at the top of `WhyThisWeightSheet`; padding inside target-display band in `PlateCalculatorSheet` |
| xl | 24pt | Spacing between the warm-up ramp block and the "WORK SETS BEGIN AT" footer row; bottom safe-area filler beneath footer buttons in `WhyThisWeightSheet` and `PlateCalculatorSheet` |
| 2xl | 32pt | Empty-state top spacing in `PlateInventoryEditor` when no plates configured |
| 3xl | 48pt | (unchanged from Phase 02 — reserved for stretched empty states) |

**Exceptions (load-bearing for Phase 03):**

- **44pt minimum touch target** carries forward for all tappable controls. Specifically: the weight cell tap area in `SetRow` (which triggers `PlateStackDisclosure`) inherits the existing 44pt touch target from `SetRow`. Each `PlateTallyRow` in `PlateInventoryEditor` is 44pt tall. The "Override" and "Use {weight} ▸" buttons in `WhyThisWeightSheet` footer bar are full-height `BRUButton(.ghost)` and `BRUButton(.signal)` at 44pt (`size: .md`). Each "Skip warm-ups" text button in `WarmupRampRows` has `.frame(minHeight: 44)`.
- **Plate rectangle proportional sizing:** in `PlateStackViz` (full-size viz in `PlateCalculatorSheet`), plate rectangle width = `max(8pt, plateWeight × 0.4pt)` and height = `40pt + plateWeight × 0.8pt`. In the mini viz inside `WarmupRampRow`, height is scaled to 18pt proportionally. These are visualization metrics, not spacing tokens.
- **`WarmupRampRow` warm-up label column:** 36pt wide (not a spacing-scale multiple — dictated by the `why-weight.jsx` `gridTemplateColumns: '36px 1fr 1fr auto'` layout).
- **Calibration progress bar height:** 6pt (`bruSignal` fill on `bruPaper` background). Intentionally thin for density — the bar is a readout, not a CTA.

## Interaction Patterns

### `WhyThisWeightSheet` disclosure flow

1. User is in `SessionLoggerView`. Working `SetRow` weight cell area shows the prescribed weight as a `BRUMono` 13pt value. A sub-caption in `labelMicro` `bruMuted` shows "RPE AUTOREG" or "DOUBLE PROG" beneath the weight value in the Previous column area. No `info.circle` icon — the sheet opens via a long-press on the weight cell (or from an "inspect" button in the set-row's trailing action area, which is implementation-time TBD per planner).
2. `WhyThisWeightSheet` slides up to `.medium` detent (NOT expandable). The ink slab at the top shows the recommended weight, reps, RPE. Below, the `BRUSectionHead("Why this weight", right: "−")` labels the disclosure section. Three numbered step blocks follow.
3. If `PrescriptionExplanation.status == .calibrating(n, threshold)`: the `CalibratingProgressMeter` card renders between step 02 and step 03, showing a signal-filled progress bar at `n/threshold * 100%` with the "CALIBRATING · n / threshold SETS" label and "RANGE ± N% {unit}" label.
4. If `status == .calibrated`: no meter. Step 02 sub-copy reads "Calibrated · weighted-mean e1RM across {n} sets."
5. Footer bar: `BRUButton(.ghost)` "Override" (left, dismisses sheet without accepting) and `BRUButton(.signal)` "Use {weight} ▸" (right, writes `roundedWeight` to the weight cell and dismisses).
6. Swipe-down dismisses without state change.

### Plate-stack inline disclosure flow

1. User taps the weight cell area in a `SetRow`. `PlateStackDisclosure` slides in below the row with an instant height reveal (no animation when `@Environment(\.accessibilityReduceMotion)` is true; 150ms ease-in-out otherwise). The disclosure panel uses `bruBg2` fill with a 2pt `bruInk` bottom rule.
2. `PlateStackViz` renders inside the disclosure with the current weight value (from `SetEntry.actualWeight` if set, else `prescribedWeight`).
3. Tapping the weight cell again collapses. Tapping a different row's weight cell opens that disclosure and collapses this one via the shared `expandedPlateSetID` `@Binding` on `SessionExerciseCard`.
4. If no plate solution exists: the `PlateStackViz` is replaced by "NO COMBINATION FOUND. ADJUST INVENTORY." in `labelSmall` 10pt `bruSignal`.

### Bump banner flow

1. At session start, `DoubleProgressionStrategy` sets `bumpOccurred: Bool = true` in `PrescriptionExplanation` when all working sets from the previous session hit the top of the rep range.
2. `SessionExerciseCard` renders `BumpBannerSlab` at its very top (above the column-header row) when `bumpOccurred && !bannerDismissed` (local `@State`).
3. The banner is dismissed on first tap anywhere on the exercise card — `onTapGesture` on the card's outer container sets `bannerDismissed = true`. The banner does not reappear in the same session.
4. RPE-autoreg exercises do NOT show a bump banner.

### Warm-up ramp insertion flow

1. `SessionFactory.start(...)` calls `WarmupRamp.shouldGenerate(for:in:)` for each `SessionExercise` in `orderIndex` order. The first qualifying one (compound + barbell/dumbbell + working weight ≥ 1.5× bar + not deload + `WarmupConfig.enabled != false`) gets ramp generation.
2. `WarmupRamp.generate(top:bar:plates:)` returns 4 `SetEntry` rows (2 for dumbbells) with `isWarmup = true`, `orderIndex` 0–3, weights plate-rounded DOWN.
3. `SessionExerciseCard` reads `setEntries` sorted by `orderIndex`. Rows with `isWarmup == true` render via `WarmupRampRows` above working rows.
4. `BRUSectionHead("Warm-up ramp", right: "Plate {increment} · ×2 sides")` heads the ramp block. A `BRUSectionHead` equivalent line "WORK SETS BEGIN AT · {weight} {unit}" (with the value right-aligned in `displayMedium` 18pt) serves as the divider before working sets. This matches the `why-weight.jsx` footer `<div style={{ padding: '10px 16px'... }}>WORK SETS BEGIN AT · 205 LB</div>`.
5. "SKIP WARM-UPS" ghost text button below the last `WarmupRampRow` marks all warmup `SetEntry.isComplete = true` and collapses the ramp block to a single muted line "WARM-UPS SKIPPED." `labelSmall` 9pt `bruMuted`.

### `PlateInventoryEditor` navigation

- Reachable from `SettingsView` → `BRUSectionHead("SMART PROGRESSION")` → `NavigationLink` "Plate Inventory" → push `PlateInventoryEditor`.
- Segmented tab row for 4 equipment kinds. Each tab: `bruInk`-styled segment (selected = ink fill paper label, unselected = paper fill ink label, 1.5pt `bruInk` border around the segmented control). NOT `TabView(.segmented)` default styling — override via `.colorMultiply(.bruInk)` or apply a custom `UISegmentedControl.appearance()` with ink/paper colors.
- Tally-mark counter rows are touch-target 44pt tall. Tapping a tally box cycles count (0 → 1 → 2 → 3 → 4 → 0). Holding does nothing — no long-press. A `Stepper` is NOT used on-card; the tally-mark visualization IS the input affordance (matching the `plate-calc.jsx` mockup's visual tally approach). The `Stepper` from v1 is replaced.
- "Reset to defaults" is a `BRUButton(.ghost)` footer — plain ink ghost, NOT signal, because it is a destructive-ish action (replaces user data).
- The `PlateCalculatorSheet` is accessible from the `BRUHeaderBar` right "•••" menu on `PlateInventoryEditor`.

| `PlateTallyRow` | `accessibilityLabel` = "{weight} {unit} plate". `accessibilityValue` = "{count} per side". `accessibilityAdjustableAction` increments/decrements the count (matching `Stepper` behavior even though the visual is tally marks). |
| `CalibratingBadge` | `accessibilityLabel` = "Calibrating: {n} of {threshold} sets logged. Weight shown as a range." `accessibilityAddTraits(.isStaticText)`. NOT hidden — it is informational. |
| `PlateStackViz` | Individual plate rectangles have no separate accessibility elements. The combined `accessibilityLabel` on the enclosing `accessibilityElement(children: .ignore)` provides the full plate description. The rotated weight numerals are decorative — their information is captured in the accessibility label. |
| Dynamic Type | All Phase 03 copy uses `BRUFont` pt sizes. The `WhyThisWeightSheet` and `PlateInventoryEditor` use scrollable `LazyVStack` / `List` — content wraps gracefully at `accessibilityExtraExtraExtraLarge`. The `PlateStackViz` inline in `WarmupRampRow` switches to a text-only fallback (plate list string only, no visual) when Dynamic Type exceeds `accessibilityExtraLarge` OR when `@Environment(\.accessibilityReduceMotion)` is true. |
| Reduced motion | `PlateStackDisclosure` slide-in animation is disabled (instant reveal) when `@Environment(\.accessibilityReduceMotion)` is true. No other animations in Phase 03 surfaces. |
| Color | Plate rectangles are ALL `bruInk` (no color-coded tiers). Information is carried by the weight numeral printed on each plate, not by color. This ensures accessibility for color-blind users without any fallback needed. |
| Haptics | No new haptic patterns in Phase 03. The set-completion success haptic from Phase 02 (`UINotificationFeedbackGenerator(.success)`) is unchanged. |
