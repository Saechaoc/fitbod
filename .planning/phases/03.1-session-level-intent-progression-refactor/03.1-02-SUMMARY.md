## Decisions Made

- **File-backed open-V3 → reopen-as-V4 is the canonical pattern for the end-to-end tests.** Plan 01 documented this in TODO blocks; Plan 02 implements it verbatim. The alternative — dual-schema in-memory containers — is impossible at Plan 02 time too, because `SchemaV3.Routine` (nested standalone @Model) and `fitbod.Routine` (top-level production V4-shape, aliased via `SchemaV4.Routine`) would both want to register as the entity "Routine" in the same store and SwiftData rejects that. The file-backed pattern sidesteps this because each container open uses ONE schema; SwiftData sees a V3-shape store, then sees a V4-schema request, walks the migration chain, and rewrites the on-disk file. The migration closure is invoked exactly once per reopen — verified by reading `v4Routines.first?.intentRaw` directly.
- **Drop the SessionExercise bottom extension entirely** (not just the `intent` / `progressionKind` accessors). After Plan 02, SessionExercise has no computed accessors at all — its only ones lived in that extension. Keeping an empty extension block would be cosmetic clutter. RoutineExercise still has its bottom extension because `warmupOverride: WarmupConfig?` (a JSON-codec accessor over `warmupOverrideData: Data?`) is a separate concern; that accessor was kept untouched per the plan's done criteria.
- **Two atomic commits, not one mega-commit.** The plan's `<interfaces>` block warned that the parse-clean intermediate state between commits is brittle (Task 2's field-writes reference `routine.intentRaw` which doesn't exist on the V3-shape Routine — so Task 2's uncomment WOULD FAIL to parse if Task 1's field additions hadn't already landed). Execution preserved the ordering: Task 1's model reshape committed first (parse-clean intermediate state confirmed by `xcrun swiftc -parse` exiting clean), then Task 2's containers + uncomment + tests committed second. Both commits are individually parse-clean.
