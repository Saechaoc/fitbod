## Decisions Made

- **BLOCKER 2 internal swap lives in Plan 03's SessionFactory work, not Plan 07.** Plan 07's frontmatter previously implied this work but never owned it explicitly as a task. Plan 03 owns SessionFactory.swift and the snapshot pipeline; therefore the internal `fetchHistoryPoints` + `lastSessionWorkingReps` swap is part of Plan 03's Task 1 step 5. The plan-checker correctly flagged this as a missing task. Without the swap, SessionFactory does not compile after Plan 02 lands.
- **Single strategy per session (D-14) via stateless-reuse, not memoization.** The hoisted `sessionStrategy` is one constructed instance that's referenced N times inside the loop. Alternative approaches considered: (1) wrap `ProgressionStrategyFactory.make` in a memoizing cache — rejected because the cache key (ProgressionKind) is now fixed for the whole session, so memoization is the same as hoisting; (2) make `ProgressionStrategy` conformers actor-isolated — rejected as overkill for stateless types. The chosen pattern is the minimum-touch fix.
- **Mirror PreviousMatchingIntent's pattern inside SessionFactory's two internal helpers, even though PreviousMatchingIntent will be reshaped in Plan 07.** At Plan 03 commit time, the three queries (PreviousMatchingIntent.fetchTopWorkingSet, SessionFactory.fetchHistoryPoints, SessionFactory.lastSessionWorkingReps) do NOT all use exactly the same shape — PreviousMatchingIntent still has its Plan-02 shape with `se.intentRaw == targetIntent` in the #Predicate. After Plan 07 lands, PreviousMatchingIntent will switch to the same shape Plan 03 uses (predicate on exerciseID only, intent gate via Swift post-filter). The plan accepted this temporary asymmetry — Plan 07 closes it.
- **Delete AddUnplannedExerciseButton's defaultIntent helper entirely, not preserve it as dead code.** The helper would compile and run, but the heuristic ("compound + barbell → strength; else hypertrophy") becomes architecturally wrong under the PIVOT semantics — the session's intent is whatever the user picked when starting the workout, not what a per-exercise heuristic suggests. Keeping the dead helper would invite future readers to reintroduce per-exercise intent logic by accident. Deletion is the right call.
- **Wire a parent Session into SwapExerciseSheet's #Preview block, don't just delete the se.intentRaw write.** Minimum-touch fix would be to just delete the `se.intentRaw = Intent.strength.rawValue` line. But that leaves the preview exercising the `.strength` FALLBACK path in the new `?? Intent.strength.rawValue` expression — not the real `session.intentRaw` read path. Adding a `Session` into the preview with `session.intentRaw = Intent.strength.rawValue` and `se.session = session` keeps the preview meaningful as a visual regression target.
- **Group the new routine-level intent + progression copy lines together with an anchor comment.** Alternative was to interleave them with the existing scalar copies (alphabetical or grouped-by-type). The grouped-with-anchor approach makes the new PIVOT-01 lines visually distinct, easier to spot in code review, and easier to revert as a unit if the PIVOT-01 decision ever gets walked back. Same rationale applied to the SessionFactory snapshot block.
